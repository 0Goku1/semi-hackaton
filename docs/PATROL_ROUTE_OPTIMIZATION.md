# 순찰 동선 최적화 설계 (향후 계획 발표용)

> 화성시 산불 대응 · 본선 3주
> 격자 해상도 **500m** (국가지점번호, EPSG:5179) — 위험도 예측과 동일 격자·동일 ID
> 근거 수치는 모두 `data/` 실측값과 실제 솔버 실행 결과 (등산로 201구간 90.4km, 임도 12.9km)
> 임도 연장은 클립 범위에 따라 다르다. 그래프 구축은 화성 extent 내 12.9km, 접근 커버율 계산은 extent+3km의 22.7km를 쓴다.
> 검증 스크립트: `analysis/09_network.py`(네트워크 구조), `analysis/10_solver_bench.py`(솔버 성능), `analysis/11_access_coverage.py`(접근 커버율)

**격자 수 표기 주의:** 이 문서는 산림이 조금이라도 걸치는 **2,513개** 격자를 분모로 쓴다. 접근성 한계를 과소평가하지 않으려면 자투리 숲까지 포함해야 하기 때문이다. 반면 `docs/FEATURE_SCHEMA.md`의 학습 테이블은 산림 점유율 10% 이상인 **1,553개**만 쓴다. 목적이 달라서 분모가 다른 것이고, 격자 ID 체계와 해상도는 완전히 동일하다.

**핵심 요약:** 위험 격자가 산출된 뒤의 순찰 배치는 **Team Orienteering Problem(TOP)** 으로 정식화하고 **Google OR-Tools**로 해결한다. 이동비용은 직선거리가 아니라 **산림청 등산로 데이터의 실측 상행·하행 소요시간**을 쓰고, 화성시 산림이 **24개 단절 구획**으로 흩어져 있는 구조를 반영해 **차량·도보 2계층 이동 모델**을 적용한다. 요원 5명에 위험 격자 20개를 배정하는 데 **0.2초**가 걸려 실시간 응답이 가능함을 실측으로 확인했다.

## 데이터를 열어보고 확인한 3가지

### 1. 등산로에 공식 실측 소요시간이 들어 있다 — 기회

`PMNTN_UPPL`(상행 분), `PMNTN_GODN`(하행 분) 두 필드가 201구간 전부 채워져 있다. 길이로 역산하면 상행 3.38 km/h, 하행 4.87 km/h, 하행/상행 시간비 0.68로 물리적으로 타당하다.

| 구간 길이 | 상행 | 하행 | 역산 상행속도 |
|-----------|------|------|---------------|
| 0.57 km | 10분 | 7분 | 3.40 km/h |
| 1.37 km | 24분 | 17분 | 3.42 km/h |
| 1.11 km | 20분 | 14분 | 3.34 km/h |

**의미:** 이동비용을 직선거리나 추정 함수(Tobler·Naismith)로 만들 필요가 없다. 산림청 공식 실측치를 그대로 간선 가중치로 쓴다. "직선거리로 가까운 순서" 배치와 결과가 달라지는 지점이고, 심사 질의에 근거를 댈 수 있는 부분이다.

### 2. 등산로 90.4km가 24개 섬으로 쪼개져 있다 — 설계 제약

끝점을 20m 허용오차로 붙여 그래프를 만들면 노드 217 · 간선 201에 연결 컴포넌트가 24개다. 가장 큰 조각도 11.2km로 전체의 11%뿐이다.

| 구분 | 컴포넌트 수 |
|------|-------------|
| 등산로 단독 | 18개 |
| 임도 단독 | 6개 |
| 등산로 + 임도 합침 | **24개 (= 18 + 6)** |

합쳐도 개수가 줄지 않는다는 것은 **두 망이 서로 접속하는 지점이 0개**라는 뜻이다. 조각끼리 가장 가까운 이웃까지도 중위 2.2km 떨어져 있어 도보로 이을 수 없다.

**그래서 이동 모델을 2계층으로 나눈다.** 같은 산 안에서는 등산로 도보(실측 소요시간), 산과 산 사이는 차량 도로 이동. 한 겹 그래프에 최단경로를 돌리면 대부분의 쌍이 "도달 불가"로 나와 배정이 실패한다.

주요 컴포넌트 (중심 격자는 국가지점번호 500m):

| 순위 | 연장 | 중심 격자 |
|------|------|-----------|
| 1 | 11.17 km | 다사 094 030 |
| 2 | 9.11 km | 다사 100 034 |
| 3 | 7.92 km | 다사 062 017 |
| 4 | 6.72 km | 다사 094 011 |
| 5 | 7.59 km | 다바 103 198 |

### 3. 접근 경로 커버율은 격자 개수가 아니라 면적으로 봐야 한다 — 한계 공개

500m 격자에 산림이 걸치는 격자는 **2,513개**(면적 overlay 기준), 그중 등산로·임도가 관통하는 격자는 **177개(7.0%)** 다. 그런데 이 7%는 두 가지 이유로 실제보다 비관적이다.

**(a) 격자 개수는 분모가 잘못됐다.** 2,513개 격자의 평균 산림 점유율은 25.7%(격자 25ha 중 산림 7ha)에 불과하다. 점유율 10% 미만인 자투리 격자가 923개(36.7%)인데 이들의 산림 면적 기여는 전체의 5.4%뿐이다.

| 격자당 산림 점유율 | 격자 수 | 격자 비중 | 산림 면적 | 면적 비중 |
|---|---|---|---|---|
| 0~10% | 923 | 36.7% | 8.7 km² | 5.4% |
| 10~25% | 627 | 25.0% | 25.7 km² | 15.9% |
| 25~50% | 513 | 20.4% | 46.8 km² | 28.9% |
| 50~75% | 274 | 10.9% | 41.7 km² | 25.8% |
| 75~100% | 176 | 7.0% | 38.6 km² | 23.9% |

**(b) "격자를 관통해야 접근 가능"은 과도하게 엄격하다.** 실무에서는 격자 경계 밖 등산로에서 진입한다. 접근점을 격자 밖까지 허용하면:

| 접근 판정 | 격자 수 | 격자 비중 | 포함 산림 면적 | 면적 비중 |
|---|---|---|---|---|
| 관통 (0m) | 177 | 7.0% | 22.9 km² | 14.2% |
| 250m 이내 | 298 | 11.9% | 32.2 km² | 19.9% |
| 500m 이내 | 422 | 16.8% | 39.7 km² | 24.6% |
| 1km 이내 | 674 | 26.8% | 57.3 km² | 35.5% |
| 2km 이내 | 1,157 | 46.0% | 91.1 km² | 56.4% |

**접근성은 산림 밀도와 양의 상관을 보인다.** 산림 점유율 75% 이상 격자는 25.0%가 등산로 관통이고 1km 초과는 52.3%인데, 5% 미만 격자는 관통 1.4% · 1km 초과 82.8%다. 실제 산에는 등산로가 있고, 접근로가 없는 곳은 대부분 마을 사이 자투리 숲이다.

**남는 한계:** 등산로 종점에서 격자 내부까지의 마지막 도보 구간은 경로 데이터가 없어 소요시간이 추정치다. 실측으로 바꾸려면 현장 답사가 필요하고 3주 내에는 불가능하다. 단, 위 거리는 등산로·임도까지의 거리이지 일반 도로까지가 아니므로, 도로망(OSM)을 붙이면 실제 도보 구간은 크게 줄어들 여지가 있다.

## 시스템 파이프라인

| 단계 | 내용 | 시점 |
|------|------|------|
| **1. 이동 네트워크 그래프 구축** | 등산로 + 임도 + 도로망을 하나의 가중 그래프로 병합. 간선 가중치는 거리가 아니라 **분(minute)**. 등산로는 `PMNTN_UPPL`/`GODN` 실측치, 임도는 도보 4km/h, 도로는 차량 30km/h + 환승 6분 | 사전 1회 구축 후 캐시 |
| **2. 위험 격자 → 방문 지점 매핑** | 예측 모델이 낸 격자 등급을 읽고, 각 격자의 순찰 대표점(격자 내 등산로 위 지점, 없으면 최근접 접근점)을 그래프 노드로 스냅. 요원 GPS도 같은 방식 | 버튼 클릭 시 |
| **3. 이동시간 행렬 계산** | 지점 전체 쌍에 Dijkstra. 같은 컴포넌트면 도보 시간, 다른 컴포넌트면 차량 시간. **25×25 실측 1.3ms** | 버튼 클릭 시 |
| **4. OR-Tools 배정** | TOP를 풀어 요원별 방문 순서 결정. 근무시간 상한, 체류시간, 위험등급 우선순위, 중복 방문 금지를 제약으로 선언. **0.2초** | 버튼 클릭 시 |
| **5. 경로 출력** | 요원별 경로선 GeoJSON + 방문 순서. 목표 격자를 국가지점번호(예: 다사 094 030)로 병기 — 등산로 실제 표지판과 같은 ID 체계 | 응답 |

### 경로는 3구간으로 구성된다

| 구간 | 이동 수단 | 소요시간 산출 | 정확도 |
|------|-----------|---------------|--------|
| 1. 차량 | 도로망 | 도로 속도 기반 | 도로망 도입 후 정확 |
| 2. 도보(안내) | 등산로·임도 | 산림청 실측 소요시간 | **분 단위 정확** |
| 3. 도보(비안내) | 경로 없음 | 직선거리 × 보행속도 | 추정치 |

### 3구간 거리에 따라 순찰 강도를 차등한다

마지막 도보 구간을 무제한 허용하면 경로도 모르는 구간에 근무시간을 낭비한다. 산림 50% 이상 격자의 3구간 거리 중위값이 1,510m인데, 3.4km/h로 편도 27분·왕복 53분이라 180분 근무의 30%에 해당한다. 그래서 접근성으로 순찰 유형을 나눈다.

| 3구간 거리 | 순찰 유형 | 처리 |
|---|---|---|
| 300m 이하 | **진입 순찰** | 격자 내부까지 도보 진입, 체류 15분 |
| 300m~1km | **근접 감시** | 등산로 상 조망 지점까지만 이동, 격자 내부는 육안 확인 |
| 1km 초과 | **원거리 감시** | 차량 이동 중 조망 또는 감시탑·드론 대상으로 이관, 도보 배정 제외 |

OR-Tools에서는 유형별로 체류시간과 미방문 페널티를 다르게 주면 그대로 표현된다. "접근 불가 격자를 버린다"가 아니라 "접근성에 따라 순찰 강도를 3단계로 차등 배정한다"가 된다.

## 알고리즘 선택

후보를 다 놓고 비교하면 요구조건(요원 여러 명 · 근무시간 상한 · 위험등급 우선 · 전부 못 돌 수도 있음)을 동시에 만족하는 건 하나뿐이다.

| 문제 정식화 | 다수 요원 | 시간예산 | 위험도 우선 | 선택적 방문 | 판정 |
|-------------|-----------|----------|-------------|-------------|------|
| TSP (외판원) | 불가 | 없음 | 없음 | 전부 방문 | 요원 1명 전제 — 탈락 |
| mTSP / CVRP | 가능 | 가능 | 없음 | 전부 방문 | 예산 초과 시 해 없음 — 탈락 |
| **Team Orienteering Problem** | **가능** | **가능** | **가능** | **가능** | **요구조건 전부 충족 — 채택** |
| 최대커버입지 (MCLP) | — | — | 가능 | — | 지점 선정용, 순서 없음 — 보조 |
| 강화학습 (RL) | 가능 | 가능 | 가능 | 가능 | 학습데이터·기간 부족 — 배제 |

### 구현: Google OR-Tools Routing (Apache 2.0)

TOP를 직접 코딩하지 않고 제약을 선언해서 만든다.

| 요구사항 | OR-Tools 표현 |
|----------|---------------|
| 근무시간 상한 | `AddDimension(누적시간, 상한 180분)` |
| 격자당 체류시간 | 전이 콜백에 +15분 |
| '높음' 필수 방문 | `AddDisjunction(페널티 100,000)` |
| '보통' 선택 방문 | `AddDisjunction(페널티 400)` |
| 중복 방문 금지 | 라우팅 모델 기본 성질 |
| 요원 GPS에서 출발 | 차량별 start 노드 지정 |

우선순위를 가중치가 아니라 **미방문 페널티**로 넣는 것이 핵심이다. 등급이 오르면 페널티가 커져서, 시간이 부족할 때 자동으로 낮은 등급을 먼저 버린다.

### 기술 스택

| 역할 | 선택 |
|------|------|
| 그래프 · 최단경로 | NetworkX (Dijkstra) |
| 경로 최적화 | OR-Tools Routing Solver |
| 공간 연산 | GeoPandas / Shapely |
| 격자 ID 변환 | 국가지점번호 (자체 구현 `src/grid.py`) |

| API | FastAPI (기존 서버 확장) |
| 지도 표시 | 카카오맵 (기존 프론트) |

500개 격자 · 요원 20명(화성시 산림 격자 전체를 위험으로 가정한 최악 시나리오)도 2초 제한 안에서 해가 나온다. 실제 규모(20~50 격자)는 여유가 크다. 배정 격자 수가 전체보다 적은 것은 근무시간 제약 때문에 낮은 등급을 의도적으로 버린 결과다.

### 배정 출력 예시 (위험격자 20개 → 요원 5명)

| 요원 | 배정 격자 | 소요 | 방문 순서 |
|------|-----------|------|-----------|
| 요원 1 | 5 | 157분 | 보통 → 보통 → **높음** → 보통 → **높음** |
| 요원 2 | 3 | 158분 | **높음** → 보통 → 보통 |
| 요원 3 | 4 | 148분 | 보통 → **높음** → 보통 → 보통 |
| 요원 4 | 4 | 132분 | 보통 → 보통 → 보통 → 보통 |
| 요원 5 | 3 | 176분 | **높음** → 보통 → 보통 |

위험격자 20개 중 19개 배정, '높음' 5개는 전부 포함. 미배정 1개는 '보통' 등급으로, 어느 요원에게 붙여도 180분을 넘겨서 솔버가 페널티를 감수하고 버린 격자다. 요원별 소요가 132~176분으로 고르게 분산된 것은 부하 균형이 작동한 결과다.

## 차별점으로 내세울 부분

1. **거리가 아니라 실측 소요시간으로 배정** — 직선거리 기준이면 가까운 격자를 먼저 배정하지만, 급경사 등산로는 같은 거리에 시간이 배로 든다. 산림청 공식 상행/하행 소요시간을 간선 가중치로 써서 "실제로 몇 분 걸리는가"로 순서를 정한다.
2. **차량·도보 2계층 이동 모델** — 화성시 산림이 24개 조각으로 흩어져 있어 산 사이는 차로 이동하고 산 안에서만 걷는다. 데이터에서 확인한 구조를 모델에 그대로 반영하고 하차·주차 시간까지 비용에 넣는다.
3. **국가지점번호로 현장 지시** — 위험도 격자, 순찰 목표, 요원 보고가 모두 같은 ID 체계. 등산로에 이미 설치된 국가지점번호 표지판과 동일하므로 요원이 앱 없이도 위치를 확인·전달할 수 있다.
4. **우선순위와 시간의 트레이드오프를 명시적으로 처리** — '높음'은 반드시 방문, '보통'은 시간이 남으면 방문. 미방문 페널티 차이로 구현하므로 시간이 부족할 때 무엇을 포기했는지 로그로 설명할 수 있다.

## 발표 문구안

> 위험 격자 산출 이후의 순찰 배치는 Team Orienteering Problem으로 정식화하고 Google OR-Tools로 해결한다. 이동비용은 직선거리가 아니라 산림청 등산로 데이터의 실측 상행·하행 소요시간을 사용하며, 화성시 산림이 24개 단절 구획으로 흩어져 있는 구조를 반영해 차량·도보 2계층 이동 모델을 적용한다. 요원 5명에 위험 격자 20개를 배정하는 데 0.2초가 소요되어 실시간 응답이 가능함을 실측으로 확인했다.

수치가 전부 실측이므로 심사 질의에 근거를 댈 수 있다. 반대로 아직 없는 것(도로망, GPS 수집)은 위 표대로 "향후"에 남겨두는 편이 안전하다.
