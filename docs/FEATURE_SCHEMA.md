# 피처 스키마 확정안

> 팀원 제안 9필드 검증 결과 + 수정 제안
> 격자 해상도 **500m 확정** (국가지점번호 체계, EPSG:5179) — 아래 모든 수치는 500m 기준 재계산 값
> 판정 근거는 임상도·입지토양도·임도망도·등산로 원본을 geopandas로 직접 집계한 실측치
> 검증 스크립트: `analysis/12_grid500_features.py` (500m 전체 지표), `analysis/11_access_coverage.py` (접근 커버율)

**핵심 요약:** 큰 방향은 맞다. 다만 그대로 구현하면 두 곳에서 반드시 실패한다. **임도근접도는 변별력이 없고**, **산불발생기록을 피처 자리에 두면 라벨 누출**이 발생한다. 나머지는 형태만 바꾸면 전부 구현 가능하다.

## 임도근접도를 빼야 하는 이유

"필요한 필드인지 확인"이 질문이었으므로 실제로 거리를 계산했다. 결론은 **개념은 옳지만 화성에서는 임도로 구현하면 안 된다**는 것이다.

계산 기준은 `등산로_화성시` 파일 201구간 90.4km와 화성 extent+3km 안의 임도 11구간 22.7km다. 연장 차이는 4배지만 **분포 차이가 훨씬 크다.** 임도는 500m 이내 셀이 1.5%뿐인데 등산로는 16.8%로 11배 차이가 나고, 임도 거리는 대부분의 셀이 "멀다"는 한 구간에 몰려 트리 분할 기준으로 삼을 지점이 없다.

> 개선 여지: 여기서는 화성시 등산로 파일만 썼다. `등산로_전국`을 화성 경계 밖까지 버퍼로 잘라 쓰면 인접 시(수원·오산·용인) 등산로에서의 진입도 반영되어 거리가 더 줄어든다. 시간이 남으면 교체할 값어치가 있다.

### 거리 임계값별 포함 셀 비율 (500m 셀 2,513개, 격자 경계 기준)

| 임계값 | 임도 근접도 | 등산로 근접도 |
|--------|-------------|---------------|
| 관통 (0m) | 0.5% | 7.0% |
| 100m | 0.6% | 8.8% |
| 250m | 0.9% | 11.9% |
| 500m | 1.5% | 16.8% |
| 1km | 2.9% | 26.8% |
| 2km | 7.4% | 45.8% |
| 5km | 28.8% | 82.2% |

| 항목 | 임도 (배제) | 등산로 (채택) |
|------|-------------|---------------|
| 중앙값 | 7,840 m | 2,229 m |
| 사분위 | 4,480~13,423 m | 905~4,010 m |
| 최대 | 22,329 m | 19,390 m |
| 평가 | 대부분의 셀이 "멀다"는 한 구간에 몰려 정보가 거의 없음 | 근거리~원거리 고르게 퍼져 접근성 피처로 작동 |

**접근성 피처 자체는 오히려 중요하다.** 한국 산불의 대부분이 입산자 실화, 논밭두렁 소각, 쓰레기 소각 같은 사람 활동에서 시작되므로 "사람이 닿는 거리"는 강력한 피처다. 아이디어 방향은 정확하다. 다만 화성에서 그 역할을 할 수 있는 것은 임도가 아니라 등산로이며, 두 근접도의 상관계수가 **0.380**에 불과하므로 임도를 등산로로 대체하는 것은 정보 손실이 아니라 개선이다.

## 수종을 이름 하나로 적을 수 없는 이유

500m 셀 2,513개 전수로 셀 안에 실제로 몇 종이 들어오는지 계산했다.

| 항목 | 값 |
|------|-----|
| 셀 내 수종 수 | 중앙 **5종**, 평균 5.1종, 최대 13종 |
| 2종 이상 섞인 셀 | **90.0%** (단일 수종 셀 10.0%) |
| 최빈 수종 면적 점유율 | 중앙 **50.6%**, 하위 25% 37.6% |
| 최빈 수종이 면적 50% 미만인 셀 | **48.8%** |
| 침/활/혼 대분류로도 2개 이상 섞인 셀 | **88.0%** (대분류 최빈 점유율 중앙 63.5%) |

**500m 셀에 수종 이름을 하나 배정하면 셀의 절반에서 사실과 달라진다.** 대표 수종이 면적의 절반도 못 채우기 때문이다. 100m였다면 최빈 점유율 중앙값이 70.4%로 그나마 버틸 수 있었지만, 500m로 확정한 이상 범주형 최빈값은 쓸 수 없다.

따라서 `수종명` 대신 **`conifer_ratio`**(셀 내 침엽수 면적 비율)를 쓴다. 정보 손실 없이 연속값으로 표현되고 부스팅 모델이 바로 학습할 수 있다. 수종 이름은 지도 팝업 설명용으로만 남긴다.

실측 `conifer_ratio` 분포: 평균 0.319, 중앙 0.272, 침엽수가 전혀 없는 셀 16.7%, 0.5 이상인 셀 24.5% (화성 전체 침엽수 면적 비율 31.2%)

## 가장 위험한 두 가지

### 1. 산불발생기록을 피처 목록에 두면 모델이 정답을 베낀다

제안된 9개 필드가 한 줄에 나란히 있으면, 산불발생기록은 같은 격자·같은 시각의 **결과값**이다. 이걸 입력으로 주면 학습은 정확도 99%가 나오고 실제 예측은 전혀 못 한다.

해결은 두 컬럼으로 쪼개는 것이다. 예측 대상은 `fire_occurred`(0/1)로 따로 두고, 입력으로 쓸 과거 이력은 `fire_count_prev_5y`처럼 **예측 시점 이전 기간만 집계한** 별도 컬럼으로 만든다. 이 구분을 문서에 못 박아두지 않으면 나중에 반드시 섞인다.

### 2. 민원빈도는 종류에 따라 답을 미리 알려주는 값이 된다

산불 신고·연기 목격 민원이라면 그것은 산불의 **결과**이므로 위 1번과 똑같은 누출이다. 반대로 불법 소각, 쓰레기 투기 같은 **사전 민원**이라면 사람 활동을 나타내는 좋은 선행 지표다.

확보 전에 세 가지를 확인해야 한다. 민원 종류를 구분할 수 있는가, 주소가 격자로 매핑될 정밀도인가, 접수 일시가 남아 있는가. 하나라도 안 되면 건물밀도나 인구밀도로 대체하는 편이 빠르다.

## 빠져 있어서 반드시 넣어야 하는 필드

앞선 데이터 분석에서 변별력이 확인된 항목 중 제안 스키마에 없는 것들이다. 위쪽 세 개는 빠지면 성능이 눈에 띄게 떨어진다.

| 추가 필드 | 단위 | 왜 필요한가 |
|-----------|------|-------------|
| `aspect_sin` / `aspect_cos` | -1~1 | 사면방위. 남향계(SE+S+SW) 48.2%로 최다이고, 화성은 셀 고도 중앙값이 41.1m라 방위가 지형 변별의 최상위 축. `EIGHT_AGL`은 8방위 코드가 아니라 연속 각도이므로 `-1`(평탄지 1.7%)을 NaN 처리한 뒤 분해 |
| `conifer_ratio` | 0~1 | 침엽수 면적 비율. 화성 산림의 31.2%가 침엽수이고 잘 타는 연료를 직접 가리키는 단일 최강 피처 |
| `dry_hours` | 시간 | 마지막 강수 이후 경과 시간. 연료 건조 누적을 나타내며 산불 예측에서 가장 강한 변수군 |
| `temp_c` / `rh_pct` / `vpd_kpa` | ℃ / % / kPa | 실효습도는 일 단위라 그날 안의 변화를 못 잡는다. 시간별 건조도는 VPD가 담당 |
| `wind_u` / `wind_v` | m/s | 풍향을 각도로 넣으면 359°와 1°가 정반대로 계산된다. 성분 분해해야 사면방위와 내적 가능 |
| `month` / `is_fire_season` | 정수 / 참거짓 | 국내 산불은 2~5월과 11~12월에 집중. 계절 축이 없으면 모델이 이 패턴을 배울 방법이 없다 |
| `rain_1h_mm` | mm | 강수는 위험도를 즉시 0에 가깝게 끌어내린다. 실효습도만으로는 반영 속도가 느리다 |
| `agcls` / `height_m` | 영급 / m | 연료량 대리 변수. 셀 평균 영급 중앙 4.0(사분위 3.8~4.1)로 편중되어 단독 변별력은 보조 수준. 수고 중앙 11.0m |
| `forest_ratio` | 0~1 | 셀 내 산림 면적 비율. 격자당 평균 점유율이 25.7%에 불과해 연료 총량 차이가 크다 |

## 테이블을 셋으로 쪼개야 하는 이유

9개 필드를 한 테이블에 시간 단위로 쌓으면 경사도·수종처럼 변하지 않는 값이 매 시각 반복 저장된다.

**1,553셀 × 8,760시간 = 연간 13,604,280행**

정적 피처를 별도 테이블로 분리하면 지형·식생은 **1,553행 한 번**만 저장된다. 기상은 관측소 단위로 쌓고 조회 시점에 격자와 조인한다. 추론할 때는 현재 시각 한 줄만 필요하므로 실시간 계산 대상은 언제나 1,553행 규모에 머문다.

> 100m 격자였다면 16,141셀 × 8,760 = 1억 4천만 행이었다. 500m 확정으로 규모가 10분의 1로 줄어 3주 일정에서 반복 실험이 가능해진다.

| 테이블 | 규모 | 컬럼 |
|--------|------|------|
| `grid_static` | 1,553행 | `grid_id` `slope_deg` `aspect_sin` `aspect_cos` `elev_m` `conifer_ratio` `forest_ratio` `frtp_cd` `agcls` `height_m` `dist_trail_m` |
| `weather_hourly` | 시간별 | `stn_id` `ts` `temp_c` `rh_pct` `vpd_kpa` `eff_humidity_pct` `wind_ms` `wind_gust_ms` `wind_u` `wind_v` `rain_1h_mm` `dry_hours` |
| `fire_events` | 라벨 | `event_id` `grid_id` `occurred_at` `cause` — 여기서 `fire_occurred`(0/1)와 `fire_count_prev_5y`를 파생 |

**학습용 테이블은 조인 결과로만 만든다.** 세 테이블을 `grid_id`와 `ts`로 조인해 학습 행렬을 만든다. 이렇게 하면 정적 피처를 다시 계산할 일이 없고, 기상 파생변수를 수정해도 정적 테이블을 건드리지 않는다. 무엇보다 라벨이 물리적으로 다른 테이블에 있어서 실수로 피처에 섞일 수 없다.

## 격자 해상도 500m 확정 (2026-08-04)

전 문서·코드가 **국가지점번호 500m 격자**를 사용한다. 위험도 격자와 순찰 격자가 같은 ID를 써야 "위험 격자를 순찰 대상으로 그대로 넘긴다"는 파이프라인이 성립하기 때문이다.

**대가는 셀 내부 이질성이다.** 같은 방식으로 100m와 비교하면:

| 지표 | 100m | 500m | 영향 |
|------|------|------|------|
| 경사도 격자평균 표준편차 | 6.859° | 5.074° | 셀 간 변별력 26% 감소 |
| 2종 이상 섞인 셀 | 86.8% | 90.0% | 거의 모든 셀이 혼합 |
| 최빈 수종 면적 점유율 (중앙) | 70.4% | 50.6% | 최빈값이 셀 대표성을 상실 |
| 학습 행렬 (1년·시간) | 1억 4천만 행 | 1,360만 행 | 반복 실험 가능해짐 |

**전제 조건:** 모든 범주형 피처를 **면적 비율**로 전환해야 한다. 이걸 지키지 않으면 500m 선택이 그대로 성능 손실이 된다. 표의 `conifer_ratio`, `forest_ratio`가 그 역할이다.

## 미해결 항목 — 팀원에게 확인받아야 할 것

1. **민원 데이터의 실체.** 민원 종류 구분이 되는지, 주소가 격자로 떨어지는지, 접수 일시가 있는지. 셋 중 하나라도 없으면 이 필드는 빼고 건물밀도로 간다.
2. **산불 발생 기록의 건수와 공간 범위.** 화성시 안쪽만이라면 지도학습이 성립하지 않아 경기도 또는 전국으로 넓혀야 한다.
3. **기상 데이터의 시간 해상도.** 일 단위로만 확보된다면 실시간이 아니라 일별 위험도로 목표를 낮춰야 하고, 그 결정이 발표 시나리오 전체를 바꾼다.
